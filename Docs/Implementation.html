3D 像素画渲染：UE5 落地要点

对应工程 GTL-Render-PixelArt3D（UE 5.8，C++，不改引擎）。按管线顺序列出每一步的做法、关键参数和踩过的坑，可以直接对照源码搬进自己的项目。原理与业界方案对比见 Research.html。

1. 管线总览

整套方案的原则是：几何、动画、光照都按 3D 正常计算，只在「位置」和「画面」两处量化到像素网格。下图是一帧的数据流，橙色框是本工程新增的部分，灰色框是引擎原有流程。

2. 低分辨率渲染与整数放大

  • 接入点：一个 FSceneViewExtensionBase（模块加载阶段设为 PostConfigInit，引擎初始化后注册）。SetupViewFamily 只对游戏视口写 r.ScreenPercentage，BeginRenderViewFamily 里调用 SetPrimarySpatialUpscalerInterface 装上自己的 ISpatialUpscaler。该接口在 Renderer/Private 头文件里，Build.cs 需要把 Runtime/Renderer/Private 和 Internal 加进 PrivateIncludePaths。
  • 尺寸：显示窗口 Inner = Viewport / Scale（向下取整）。实际渲染尺寸 Render 每边至少多 2 texel 余量，留给亚像素平移；同时 Render.Y 取 Viewport.Y / gcd(Viewport) 的整数倍，保证 texel 是正方形。屏幕百分比写 (Render.Y − 0.001) / Viewport.Y × 100，避免引擎向上取整多出一行。
  • 必须关掉的东西：抗锯齿（TSR/TAAU 会接管放大）、动态分辨率、动态模糊、自动曝光、Bloom、Lumen、VSM、遮挡查询、正交近平面修正，见 Config/DefaultEngine.ini。r.CustomDepth=3 打开，描边和角色分层都用到自定义深度模板。
  • 放大着色器（Shaders/PixelUpscale.usf）：输出像素 p 取 texel floor(p / Scale + InnerOffset + SubTexel)，SubTexel 是相机吸附余量（y 取反，因为纹理 v 向下），四周黑边居中。

3. 像素网格吸附

网格以世界原点为锚、与屏幕右 / 上轴对齐，格距 = 1 texel。所有吸附都只改这两个轴上的坐标。

  • 相机：位置投影到右 / 上轴取整，余量交给放大着色器。渲染尺寸为奇数时，画面边缘落在半格上，要先加 0.5 的奇偶偏移再取整，并且「先取整再加偏移」，否则 n − 0.5 的取整会被浮点误差来回翻转。
  • 物体：只挪可见网格，Actor 保持连续（移动、碰撞都不受影响）。吸附后再沿视线方向滑回地面平面：这样两次换格之间网格在世界里完全不动；否则它会沿视线悄悄漂移，屏幕上看不出来，但它的影子会跟着漂。
  • 斜向移动：移动速度按屏幕方向等速（往屏幕上方走时世界速度 ÷ sin(俯角)），斜向时沿 45° 线整体吸附，横纵两轴在同一帧换格。是否斜走按玩家按住的方向键判断，不要按速度判断（起步时速度方向还没转过来）。
  • 骨骼（FAnimInstanceProxy::Evaluate）：每个关节相对已吸附的根节点保持整格偏移，偏离超过 0.75 texel 才换格。直接按绝对网格取整，会把走路时 0.4 格的身体起伏放大成整格跳动。脚不继承父骨骼的修正，保证落地不滑。
  • 挂件：武器挂在胸部骨骼上，不要挂在网格根上，否则身体起伏时挂件不动，两者相对跳。

4. 相机跟随：分层合成

相机吸附和角色吸附各自对网格取整。只要两者取整的不是同一个值（比如相机缓动跟随、站台取景跟角色中点），两次取整就会错拍，角色在屏幕上来回跳最多 1 格以上，背景滚动也忽快忽慢。这是「画面晃、看着晕」的主要来源。几种跟随方式的对比：

跟随方式角色在屏幕上背景滚动实测（60 fps 斜走）
缓动插值（常见写法）晃，平均 0.40 格，最大 1.18 格整格跳、节奏不均最晕
锁定像素：相机直接骑在角色吸附后的位置上纹丝不动整格跳（每 2–3 帧 4 个屏幕像素）传统像素游戏手感
平滑 + 亚像素：相机连续跟随，余量交给放大晃约半格每帧平滑背景顺、人不稳
分层（本工程默认）纹丝不动每帧平滑（直走每帧 2 屏幕像素）两者都稳
  1. 相机：跟随角色网格根的连续位置，但取景偏移（头部高度、站台取景）在屏幕右 / 上轴上保持整数 texel。这样相机吸附和角色吸附对同一个连续值取整，两者之差是常数，角色按原样显示就正好在它的真实屏幕位置上。角色这一侧用普通四舍五入，不要加回差或斜向锚定，必须和相机的取整一致。
  2. 相机读角色自己算吸附时用的那个连续位置（SnapSourceWorld），不要读 Actor 位置：碰撞可能在角色 Tick 之后又挪动 Actor，两边就取整了不同的值。
  3. 放大着色器：从 View.GetSceneTextures().CustomDepth.Stencil 读模板（取值用 STENCIL_COMPONENT_SWIZZLE）。模板等于角色 ID 的 texel 不加偏移直接取；其余加 SubTexel 后取；如果加了偏移后正好落在角色身上（背景被角色挡住的那一条，最宽 1 texel），就取朝偏移方向的相邻背景 texel 补上。
  4. HUD 和场景标记：不要用 AHUD::Project，它不知道这个偏移。按「低分辨率坐标 − InnerOffset − SubTexel（y 取反）× Scale + 黑边」自己换算，标记才会跟着地面平滑移动。
进出站台时取景偏移要缓动到新位置，过渡期间偏移按整格变化，角色和背景会小步跳约半秒。这是让角色在稳定期纹丝不动的代价。

5. 角色影子跟随角色层

角色已经单独成层，但它投在地面上的影子画在背景里，影子边缘按背景的网格取样，相对角色仍会来回错动半格。解法是把角色投在地面上的影子也放到角色层，在放大时合成：

  • 三张阴影深度图（正交 SceneCapture2D，SCS_SceneDepth，R32f，每帧 CaptureScene() 同步拍）：
    • 全场景：墙、道具等接收面使用；
    • 去掉角色的全场景：地面材质使用（地面上不再画角色影子，避免重复压暗）；
    • 只有角色（PRM_UseShowOnlyList），以吸附后的角色为中心、800 cm 宽：角色每次都落在这张图的同一位置，轮廓光栅化完全一样，影子形状相对角色不变。
  • 放大时重建世界坐标：用不加偏移的那个 texel（角色层的坐标）读场景深度，用 GetInvTranslatedViewProjectionMatrix() 还原，再减去 PreViewTranslation。直接用 GetInvViewProjectionMatrix() 在大世界坐标下不可靠，本工程里得到的点全部落在阴影图外。
  • 判定：该点在「仅角色」图里被挡、在「去角色」图里没被挡、模板是地面（ID 1）时，按地面的 toon 明暗比例压暗：pow(shade(0) / shade(q地面), 1/2.2)，q 由光照方向和色阶数在游戏线程算好传进来。
  • 墙和道具的深度被排序推移过，放大时还原不出真实位置，所以它们继续用全场景阴影图，在材质里照常算。

6. 精灵排序

  1. 两两前后：两个包围盒找一条分离轴，按视线方向在该轴上的分量判断谁在前；有多条分离轴时取「间隔 × |视线分量|」最大的那条；找不到时退回比较中心深度。屏幕矩形的重叠面积作为这条边的权重。
  2. 成环：Tarjan 求强连通分量。分量内互不相交的物体合并成一层、保留真实深度（不切任何边）；只有真正穿插时才切重叠面积最小的边（静态边代价 ×4），并记住上一帧切的边，新方案不比它好 20% 就不换（滞回），避免来回闪。
  3. 分层：Kahn 拓扑求最长路径层级。槽位深度从 相机深度 + 3200 开始逐层朝相机推进，每层 30 cm 或合并组的厚度。
  4. 写回：用自定义图元数据（CPD）把槽位、轴心、保留系数传给材质。WPO：s' = Slot + (s − Pivot) × Keep，单个物体 Keep = 0.02（压扁），合并组 Keep = 1。只在主相机下推移：判断 dot(ResolvedView.ViewForward, 相机前向) > 0.999，否则阴影拍摄也会被推歪。

三根杆两两遮挡成环的情况，在 0° 偏航下包围盒不可能真正交织，展台 ④ 需要把相机转到 45° 才能演示。

7. 光照、阴影、描边、抖动

  • 光照：Unlit 材质自己算 toon 明暗，位置用不含 WPO 的世界坐标（WorldPosition 节点选「排除所有着色器偏移」），排序推移不影响光照。这是不改引擎的关键：UE 的延迟光照用的是被推移后的深度，会算错。
  • 阴影偏移：最近邻采样的深度图在掠射角会出条纹，用法线方向偏移 5 cm 加斜率偏移 6 + 6 × min(tanθ, 6)。阴影图要在光照参数定好之后同步拍，自动每帧拍会晚一帧，光源转动时整片阴影错位。
  • 描边（后处理替换色调映射，在低分辨率下跑）：按自定义模板 ID 和深度找边，线画在较近的物体上（归前方）；地面内部按深度差找折线。再做 3×3 清理：去掉孤立点和 L 形拐角的多余点。输出 pow(col, 1/2.2) 并先除以 PreExposure。
  • 抖动：只在 toon 色阶交界附近用 4×4 Bayer 图案过渡，不要对整张图的颜色做量化。物体空间锚点（随物体走）比屏幕空间（会在移动物体上滑动）稳定。

8. 动画

  • 直接在 C++ 的 FAnimInstanceProxy::Evaluate 里采样待机 / 行走两段动画，不需要动画蓝图。
  • 阶跃关键帧：每圈固定取偶数个姿势（1.07 秒的走路取 8 个），按相位取样，不要按固定的每秒 8 帧取样。循环时长不是整数帧时，固定帧率取样每圈取到的姿势都不同，身体起伏的整格跳会时有时无，看起来像随机抽搐。
  • 阶跃模式下待机 / 行走的混合权重也取 0 或 1，中间值本身就是插值。
  • 朝向量化为 45° 一档：Actor 平滑转身，网格只显示量化后的朝向。

9. 测量与自测

命令行开关作用
-PixelCapture=<目录>离屏跑完所有展台并截图，日志里有每张图的闪烁率与排序统计
-PixelMotionTest [-PixelFollow=N] [-PixelMotionStraight]自动按住斜向或向上走 3 秒，输出角色在屏幕上的抖动、背景滚动不均匀度、斜向同步换格比例
-PixelFrameDump=<目录> [-PixelDumpFinal]逐帧导出显示的画面（低分辨率或最终放大后），配合 -benchmark -fps=60 按真实帧节奏分析
-PixelShadowMaskDebug / -PixelShadowSourceDebug把角色影子涂成洋红，或按来源分色（角色 / 世界 / 两者）
-PixelWalkTest、-PixelStartX= -PixelStartY=验证能否移动；指定起点

闪烁率用 GPU 回读：放大 pass 里把显示窗口 AddEnqueueCopyPass 到一组（6 个）轮换的 FRHIGPUTextureReadback，保证每一帧都能取到；比较相邻两帧，在 ±2 texel 内找最佳整格平移后统计仍不同的像素比例。FViewport::ReadPixels 在这条管线里取到的帧是相同的，测不出东西。场景颜色格式是 PF_FloatR11G11B10，需要自己解码。

经验：只看「相机和角色的数值误差」会漏掉问题，最终要逐帧导出画面看。本工程的身体跳格、影子漂移都是逐帧看图才发现的。
